# Authentication and custom application pilot
Authentication is required by default. For loopback browser testing run python factory/enterprise_auth.py to generate a salted scrypt password hash. In PowerShell set $env:ARINOVA_AUTH_MODE="local" and $env:ARINOVA_LOCAL_USERS='{"admin":{"password_hash":"PASTE_HASH","roles":["admin"],"projects":[]}}'. Restart policy_studio.py and open /factory; browser Basic login prompts for username and password. Never commit credentials. Other users have roles developer, quality, approver, release or viewer and explicit project IDs in projects. Admin can perform all actions. Legacy routes are admin-only; do not run separate legacy servers with sensitive data.
OIDC API mode: set ARINOVA_AUTH_MODE=oidc, ARINOVA_OIDC_ISSUER, ARINOVA_OIDC_JWKS_URL, ARINOVA_OIDC_AUDIENCE. Configure trusted issuer to emit roles and projects arrays. RS256 signature, issuer, audience, expiration, issued-at and subject verified. Browser OIDC login/PKCE and TLS proxy integration not implemented; use API bearer tokens. Audit is application logging, not immutable storage. Configure INFO logging to retain successful requests. No MFA implementation, rate limiting, separation of duties enforcement or DB RLS; external IdP and production hardening required.
Select Custom knowledge application, enter unique ID and requirements, configure, plan, generate. Upload PDFs via /factory/pdf. Custom starter contains no fictional policies; unsupported questions abstain. OpenHands must implement arbitrary business logic. Deployment scaffold for custom and newly generated policy templates includes authenticated customer API, Dockerfile and dependencies. Development copies scaffold before quality and approval. Delivered ZIP is available through /factory/release/{id} for release/approver/admin. Standalone API supports fixture retrieval only; central PDF and agents are not yet bundled. Docker unit tests do not validate the standalone API or its dependencies. No live validation performed.
